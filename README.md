# PoE Crafting Tools

A repository of Path of Exile crafting **techniques** — not just raw data, but
explanations of what each technique does, when to use it, and what it costs —
structured so it can also drive a **reverse-crafting recommender**: given an
item you want to end up with, find candidate technique sequences that could
get you there.

## Why this exists

Sites like [Craft of Exile](https://www.craftofexile.com/) simulate crafting
odds, but they don't explain *why* you'd pick one method over another, and
their underlying data/logic isn't public (see "Data sources" below). This
repo aims to be:

1. A **readable reference** — browse `techniques/` to learn what a given
   currency/system actually does and when it's the right tool.
2. A **queryable catalog** — every technique has structured tags (category,
   action, affected slots, mod tags it can hit, cost) so it can be filtered
   programmatically.
3. Eventually, a **reverse-crafting engine** — paste in a target item (or a
   Path of Building item block) and get back ranked candidate crafting
   sequences.

## Repository layout

```
techniques/<category>/<id>.md   # one technique per file: YAML frontmatter (structured) + markdown body (explanation)
schemas/technique.schema.json   # the frontmatter schema every technique file must satisfy
engine/                         # Phase 1 reverse-crafting engine (Python)
  models.py                     # ItemState, Mod, Technique, TargetSpec
  technique_loader.py           # parses techniques/**/*.md into Technique objects
  reverse_craft.py              # diffs a target against a starting item, searches candidate chains
examples/dire_stride_demo.py    # worked example, run with: python3 examples/dire_stride_demo.py
```

Each technique file is the **single source of truth** — the frontmatter feeds
the engine, and the same file (frontmatter + body) is what gets read/browsed
by a human. There's no separate data-only representation to keep in sync.

## Adding a technique

Create `techniques/<category>/<your-id>.md`, matching
`schemas/technique.schema.json`:

- `id`/`name`/`category`/`action` — what this is and what family it belongs to.
- `affects` — which slot types it touches (`prefix`, `suffix`, `implicit`).
- `mod_pool_tags` — which mod tags it can hit. Use a placeholder like
  `chosen-at-craft-time` if the specific tag is picked when you use the
  technique (e.g. which essence, which Harvest tag) rather than fixed.
- `guarantee` — `guaranteed` / `biased` / `none`.
- `destructive` — how much existing item state it wipes: `none` /
  `remove_one` / `reroll_all`.
- `preconditions` — rarity, influence, open-affix, or existing-mod
  requirements.
- `cost_tier` — rough `low`/`medium`/`high`, until real pricing is wired in.

The markdown body below the frontmatter is free-form: what it does, why
you'd use it, its limitations, and a "Data completeness" note flagging
anything that's a conceptual placeholder pending real data.

## The two-phase plan

**Phase 1 (current state of this repo):** a hand-curated catalog of
techniques plus a *rule-based* reverse-crafting engine. Given a target and a
starting item, it diffs the mod tags you still need and searches for
technique sequences that could plausibly supply them, respecting
preconditions (rarity, influence, open affix slots) and destructiveness
(never recommends wiping mods you've already locked in). It simulates the
**optimistic best case** for every guaranteed/biased technique — it does not
know real odds yet, so it answers "what's relevant here", not "what's
cheapest in expectation."

**Phase 2 (future work):** wire in real mod-pool data — weights, tiers, tag
pools per base/item level/influence — so chains can be ranked by actual
expected cost and success probability, closer to what Craft of Exile does
internally.

**Phase 3 (future work):** a generated, searchable docs site over
`techniques/` (the "user-accessible repository" piece), and a parser that
takes a pasted Path of Building/in-game item block and turns it directly into
an `ItemState`/`TargetSpec` for the engine.

## Data sources for Phase 2

Craft of Exile itself doesn't publish an API or raw dataset. The underlying
game data it (and this project, eventually) would need — mod pools, weights,
tags, tiers, essence/fossil/harvest effects — is publicly available through
community-reverse-engineered sources instead:

- **[RePoE](https://github.com/brather1ng/RePoE)** — JSON exports of mod
  pools/weights/tags generated by **PyPoE** from the game's own data files.
- **[PyPoE](https://github.com/OmegaK2/PyPoE)** — the extraction toolchain
  RePoE is built on, if you need something RePoE doesn't already export.
- **[poedb.tw](https://poedb.tw/)** — browsable mirror of the same
  underlying game data.
- **[Path of Exile Wiki](https://www.poewiki.net/)** — documents the actual
  mechanics/formulas for harvest, essences, fossils, and eldritch currency.

## Running the demo

```
python3 examples/dire_stride_demo.py
```

Requires `pyyaml` (`pip install pyyaml` if not already available). This
loads every technique in `techniques/`, sets up a simplified target inspired
by the Dire Stride boots example (flat energy shield, increased energy
shield, resistances, movement speed), and prints ranked candidate crafting
chains.
